# 签到缓存权威与独立合批落库修复

目标：修复已经确认的数据路径偏差。用户已授权按“Actor 内存→Redis→独立落库进程→MySQL”推进；沿用现有签到协议、日期与奖励规则。

## 范围与设计

- 玩家基础信息、基础属性、完整背包和签到记录作为一个带版本的快照。
- 请求先修改 Actor 的暂存内存；成功响应先缓冲。Redis Lua CAS 原子保存快照、递增版本并登记脏队列，成功后才回包。失败恢复内存，下一次从 Redis 核对未知结果。
- 登录恢复内存优先读 Redis，只有 Redis 真正缺失时才以一致性 SQL 快照回源初始化；签到查询只读 Actor。
- 每个分片的快照键和脏队列使用相同 Redis Cluster hash tag；不设置 TTL。脏队列与缓存更新同一 Lua，不能分两步发送易丢通知。
- 独立 `cmd/flusher` 定时拉取多个玩家，SQL 事务内锁版本行、批量保存基础状态/背包/签到、推进落库版本。提交后仅确认读取版本；缓存已经更新则保留脏任务。
- Redis/SQL 失败保留任务；未知 SQL 提交可重放，版本栅栏防止倒写。不在游戏服继续同步保存这部分数据。
- 保留旧模块其他实体仓储和 Tier-1 事务路径；不宣称本次已迁移全部 Tier-2 数据。
- Redis 是本次成功确认的持久化边界，其 AOF、故障恢复和 noeviction 配置决定可恢复性；不承诺 Redis 数据同时丢失时零回退。

- [ ] 先测试 Redis CAS、缓存与脏队列原子更新、版本确认、失败和重启恢复，再实现 `pkg/writebehind`。
- [ ] 先测试版本栅栏、SQL 回滚和提交后重投，再实现多玩家合批落库及独立命令。
- [ ] 接入玩家快照、Redis 优先恢复、响应缓冲和失败内存恢复；避免旧的 Actor 保存覆盖独立进程。
- [ ] 将签到仓储改为内存状态访问，SQL 仅作为冷启动回源；复用已有协议和奖励配置。
- [ ] 更新真实 Redis/MySQL 集成测试：领取时不写 SQL、定时后落库、缓存重启恢复、重复领取、普通背包变更、故障重试、旧版本不能覆盖新版本。
- [ ] 接入构建/部署入口、迁移 SQL、运行说明；校正剩余开发路线图中的数据分级。
