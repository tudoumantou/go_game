# 剩余功能开发与可靠性补齐计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Use superpowers:subagent-driven-development only when delegation is explicitly selected. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留已运行链路和七日签到的基础上，逐步补齐设计文档中的业务缺口，并修复影响数据可靠性的基础问题。

**Architecture:** 延续 Gateway → Game RPC → 玩家 Actor → Module 的业务入口，以及现有 MySQL、Redis、Kafka 和中心服分工。优先修复消息、落库和资产事务，再完善玩法；不为填满目录而搬动已有实现。每个阶段独立交付，后续子系统在启动前细化设计，不一次性大改。

**Tech Stack:** Go 1.22+、Protobuf/buf、自研 Actor、MySQL、Redis、Kafka、etcd、Docker、现有 testcontainers 测试。

**Spec:** [总体设计文档](../../game_study-服务器框架设计文档.md)第 8、9、11–18、21、23 章；[七日签到现有契约](../../signin.md)。设计文档描述目标，源码和验证结果描述当前实现。

**基线日期：** 2026-10-18。基于当前仓库静态扫描制定；状态表中的“已有”不代表已通过生产环境验收。本文为后续工作路线图，不表示已经实现。后续阶段存在多个独立子系统，执行时按任务补充单独的小计划。

## Global Constraints

- 用户当前只要求制定计划；本次不修改业务实现，不启动后续阶段。
- `pkg/pb`、`pkg/model`、`pkg/gamedata` 为生成代码，修改 `.proto`、DDL、XML 后生成，禁止手改生成物。
- `pkg/` 不依赖 `internal/`；服务间不直接 import 对方私有业务代码。
- 玩家背包由所属 Actor 管理，不新增绕过 Actor 的在线资产写入者。
- 保留签到规则：角色独立；北京时间零点；首次成功签到起七个自然日循环；漏签不可补；奖励直接入背包。
- 需要 MySQL 事务证明的业务，不以 Redis 去重、Actor 串行或 Kafka 已消费代替持久化正确性。
- 不把“发送保存消息成功”当成“数据库保存成功”；不承诺现有 Write-Behind 能在任意 kill -9 后零丢失。
- 普通状态允许的丢失窗口、严格资产的恢复保证分别定义，不能将两者混为一谈。
- 新消息号先检查占用并登记；沿用错误码规范。日期规则、业务唯一键、未知提交结果必须写入各任务设计。
- 每次只推进一个可验收任务。默认在当前会话顺序实现；不因本文存在而自动启动全部开发、提交或发布。

## Review Focus

1. 信箱满、Actor 正在退出：关键消息不得被静默挤掉；投递方必须拿到可处理的结果。由 R1.1 验证。
2. SQL 失败、超时或 COMMIT 结果未知：保存和发奖必须如实回报，安全重试不得覆盖已到账资产。由 R1.2、R2 验证。
3. 同账号顶号、重连和旧连接延迟下线：旧会话不得清理新会话或继续修改角色。由 R3.1 验证。
4. 跨零点、跨周期、离线多日：签到、商店刷新、活动和赛季都按服务端业务时间计算。由 R4.3、R7、R8 验证。
5. Kafka 重投、死信写入失败、消费后进程退出：不得既丢弃消息又提交成功。由 R1.4、R2.3 验证。

## 四、每个任务的统一交付步骤

每个 R 编号下的小任务单独执行，禁止一次勾选整个阶段而没有对应证据。

1. 确认本次要解决的一个问题、输入输出和暂不涉及的范围；新玩法先确定规则。
2. 列出准确文件、协议号、DDL、配置、接口和依赖，写本次的小计划；不照搬其他阶段尚未确定的接口。
3. 对会影响行为的代码先补能暴露问题的测试，再实现；文档和低影响配置修改使用对应检查。
4. 改协议/配置/DDL 后生成代码，检查迁移和生成一致性。
5. 运行本次定向测试；改动影响公共接口时再运行全量测试。只在新增变更或未解决风险时扩大验证。
6. 对事务与恢复路径做审查，更新状态文档和本计划的任务勾选；提交时写清验证结果。

常用验证命令（按改动选择，不要求每个任务全跑）：

```bash
go test ./...
go test -race ./pkg/actor ./pkg/flush ./internal/game/player
go test ./internal/game/module/signin ./internal/game/player
go test -tags=integration -timeout 20m ./test/integration -run '^TestSigninActorFlow$' -count=1 -v
git diff --check
```

业务成功的证据应同时覆盖：客户端结果、数据库终态、重复请求和恢复后的结果。依赖容器超时应作为环境失败记录，不能标记为业务通过或仅靠无限重试掩盖。
