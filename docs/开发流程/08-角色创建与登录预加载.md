## 按顺序实现

第一步从数据库事实开始：player 有 account_id 和唯一 name；player_attr 保存职业及基础数值。一个账号一个角色目前是应用规则，player 表只有普通 account_id 索引，不能宣称 DB 已唯一兜底。

第二步 RoleService.FindByAccount 返回明确 ErrNoRole。名字按规则校验，职业必须存在于服务端配置。创角使用事务插入 player 和 player_attr，名字冲突用驱动 1062 映射 ErrNameUsed。

第三步将 1010 EnterGame 与 1020 CreateRole 放在会话级入口处理。它们在玩家 Actor 还不存在时就必须可用；已自动绑定角色后再次 1010 仍应在入口处理，避免落到没有 1010 路由的 Module。

第四步 bindPlayer 获取/创建 Actor，维护 session→player 与 player→session 索引。BindMsg 触发首次 preload；重连 Actor 仍存活时不必每次重读同一状态。

第五步预加载五组表，等待完成后组装新 State，再通知模块 OnLogin。主角色数据缺失应该失败；装备/活动失败当前允许降级查库。不要把“部分允许降级”写成“所有错误都忽略”。

```text
第一次：Token 合法 → OnBind 无角色 → 1010 返回 2003
       → 1020 事务建角 → bindPlayer → Actor Bind → 预加载
已有角色：Token 合法 → OnBind 找到角色 → 自动绑定
         → 客户端仍可发 1010 → 返回角色与服务器时间
```

源码节选：[internal/game/service/role_service.go](../../internal/game/service/role_service.go)。这是现有包中的片段，依赖同文件类型，不是可单独运行的完整程序。

```go
func (s *RoleService) Create(ctx context.Context, accountID int64, name string, career int32) (int64, error) {
	name = strings.TrimSpace(name)
	if !namePattern.MatchString(name) || utf8.RuneCountInString(name) > 16 {
		return 0, ErrNameIllegal
	}
	if _, ok := gamedata.GetCareerCfg(int64(career)); !ok {
		return 0, ErrCareerBad
	}

	// 一个账号只允许一个角色（P6 简化，P7 支持多角色选择）
	if _, err := s.FindByAccount(ctx, accountID); err == nil {
		return 0, fmt.Errorf("account %d already has a role", accountID)
	} else if !errors.Is(err, ErrNoRole) {
		return 0, err
	}

	var roleID int64
	err := s.db.Tx(ctx, func(tx *sql.Tx) error {
		const insPlayer = `INSERT INTO player (account_id, name, level, exp, coin, scene_id) VALUES (?, ?, 1, 0, 0, 0)`
		res, err := tx.ExecContext(ctx, insPlayer, accountID, name)
		if err != nil {
			var me *mysqlDriver.MySQLError
			if errors.As(err, &me) && me.Number == 1062 {
				return ErrNameUsed
			}
			return fmt.Errorf("insert player: %w", err)
		}
		roleID, err = res.LastInsertId()
		if err != nil {
			return err
		}

		hp, mp, atk, def, spd := baseAttrs(career)
		const insAttr = `INSERT INTO player_attr (player_id, career, hp, mp, atk, def, spd) VALUES (?, ?, ?, ?, ?, ?, ?)`
		if _, err := tx.ExecContext(ctx, insAttr, roleID, career, hp, mp, atk, def, spd); err != nil {
			return fmt.Errorf("insert player_attr: %w", err)
		}
		return nil
	})
	if err != nil {
		return 0, err
	}
	// 登记 ID 表：不阻塞创角返回，失败也只是等下次对账补上
	if s.idTable != nil {
		if err := s.idTable.Add(ctx, "player", roleID); err != nil {
			s.logger.Warn("idtab add player failed", "player_id", roleID, "err", err)
		}
	}

	s.logger.Info("role created", "role_id", roleID, "account_id", accountID, "career", career)
	return roleID, nil
}
```

## 逐段解释与知识点

事务里的 LastInsertId 来自当前 INSERT，不能用 SELECT MAX(id) 猜新角色。名字正则按 Unicode 字符理解；注释提到敏感词不代表已经有词库过滤，当前实现主要做格式与职业校验。

并行五查询的耗时接近最慢查询加排队开销，不是一次 SQL，也不保证共同快照。WaitGroup 只负责结果发布时序，连接池仍可能把并行查询排队。

构造 Actor 时给初始 State 设置 dirtyHook，preload 换新 State 后，当前代码经 `Actor.setState` 重新绑定。应保留在线变更进入 Flusher 的回归；教学实现可把“安装新 State 并重绑所有依赖”封装成一个方法。

Actor Bind 入队与预加载完成之间有窗口；要在进入游戏成功语义中等待完成确认，需要带 Ack 的消息。当前 Respond 的发送者为空时不会替你通知 RPC。

## 怎么验证与定位错误

`go test -tags=integration ./test/integration/ -run 'TestP6GameplayFlow|TestP12LoginPreload' -v -timeout 10m` 会创建真实依赖容器，先保证 Docker 可用。

至少测重名、非法名、非法职业、事务第二条 SQL 失败、已有角色重进、预加载超时。新角色无装备和活动数据是正常情况，player 本体缺失不是。

## 独立练习与通过标准

给练习工程补 account_id 唯一业务约束并设计已有数据迁移；加入 BindAck，使加载失败不返回成功。通过标准：两并发建角不能绕过同账号限制，在线修改会触发脏集合。
