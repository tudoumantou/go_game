# 00 总览与阅读顺序

本课程面向“会基本 Go 语法，但没有亲手写过完整游戏后端”的读者。按章节在自己的练习工程实现，再与当前仓库比较。已有项目可先运行，不要求你先重写一遍才能看到效果。

## 1. 两条学习路线

**从零实现路线**：01–05 写工程、网络、账号；06–10 写内部通信、Actor、角色和存档；11–13 加异步事件与跨服；14–16 完成测试、部署与独立扩展。

**源码阅读路线**：先读项目解说 → 08 角色 → 09 模块 → 07 Actor → 10 存档 → 回到 03–06 网络与身份 → 其余模块。遇到不会的语言机制查知识点专题。

当前仓库构建五个服务与独立 flusher，共六个程序。第 01 章区分无外部依赖的教学程序和现有服务，第 10 章区分缓存权威持久化与非缓存保存路径。

不要拿两个工程的架构直接混合。参考项目里的 WebSocket、JSON name、xorm、独立聊天服、城池和行军不是本项目现成 API。

## 2. 准备环境

需要能正常工作的 Go（项目 go.mod 声明 1.22）、Git、Docker Engine/Desktop 与 Compose；生成协议另需 buf；部署脚本用 OpenSSL、curl、bash。先检查工具版本和编译器路径，不在教程中假定你机器上的 GOROOT 一定正确。

```bash
# 在现有仓库根目录执行，只读取环境。
go version
go env GOROOT GOTOOLDIR
docker version
docker compose version
# 先跑纯组件测试，理解目前已有的行为。
go test ./pkg/codec ./pkg/crypto ./pkg/actor
```

新建练习工程时使用独立目录，比如 `~/go_game_lab`。module 仍可叫 game_study，这样按章节移植包时 import 一致。不要在原仓库根目录再次 go mod init，不要删除原有代码来制造空工程。

## 4. 每章怎么做

先用自己的话写下目标和不变量；按文件清单实现最小接口；对照代码节选逐句理解；用给出的命令验证；故意制造一次失败；最后不看答案完成练习。遇到无法解释的 goroutine、锁或事务，先画所有权与生命周期，不急着增加组件。

“核心源码”不是一段可以孤立粘贴运行的文件，它引用前章和同包定义。带 package/import 且明确说可运行的教学例子才可单独执行。签到教程逐段讲解当前 Repo、Module 与 Actor 事务能力，用来练完整新增功能。

## 7. 学完应能回答

一条消息如何定位玩家？谁可以改玩家数据？哪一次调用只是入队？哪一次已经提交？超时能否取消已提交事务？容器启动为何还会 DNS 重试？同一奖励重复请求和进程崩溃分别如何处理？

如果这些问题还只能用“框架会处理”回答，回到对应章节画具体调用链。读完文档是开始，独立做出签到并解释失败行为才是验收。
