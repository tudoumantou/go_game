## 按顺序实现

第一步先定义 Config 字段，而不是先写读取所有键的万能 map。端口、池参数、超时各用清楚的字段；时间先保存字符串，再按约定 ParseDuration。

第二步实现 ReadFile → ExpandEnv → YAML Unmarshal → normalize → Validate。校验 server.name、env、监听地址，以及 min_idle_conns 不大于 pool_size。环境变量缺失会变空串，必要的 DSN 应启动时拒绝，不能假定 os.ExpandEnv 会报告缺失。

第三步默认 logger 在配置加载前创建；配置成功后设置级别。固定字段 service、player_id、session_id 帮你跨服务追踪，不能记录完整 Token 或密钥。当前 logger 主要输出 stdout，容器负责日志收集。

第四步区分业务错误与系统错误。重名可映射明确 code；DB 超时需要日志和重试策略。不要把任意 err.Error 原样发给客户端，也不要把所有系统错误都改成“参数错”掩盖根因。

第五步 sql.Open 后设置池参数并 PingContext。将 DB 注入 Repo。数据库表结构由 SQL/迁移维护，不在每个 HTTP 请求里建表。

```go
// 教学调用片段：完整类型与导入见 pkg/db。
database, err := db.New(db.Config{
    DSN: dsn, MaxOpen: 20, MaxIdle: 5,
})
if err != nil { return fmt.Errorf("initialize account database: %w", err) }
// 资源所有者负责在服务停止阶段 Close，业务 Repo 不随请求 Close 池。
```


## 核心源码与注释阅读

源码节选：[pkg/config/config.go](../../pkg/config/config.go)。这是现有包中的片段，依赖同文件类型，不是可单独运行的完整程序。

```go
func Load(path string) (*Config, error) {
	raw, err := os.ReadFile(path)
	if err != nil {
		return nil, fmt.Errorf("read config %s: %w", path, err)
	}
	expanded := os.ExpandEnv(string(raw))

	var cfg Config
	if err := yaml.Unmarshal([]byte(expanded), &cfg); err != nil {
		return nil, fmt.Errorf("parse config %s: %w", path, err)
	}
	cfg.normalize()
	if err := cfg.Validate(); err != nil {
		return nil, fmt.Errorf("validate config %s: %w", path, err)
	}
	return &cfg, nil
}
```

源码节选：[pkg/db/db.go](../../pkg/db/db.go)。这是现有包中的片段，依赖同文件类型，不是可单独运行的完整程序。

```go
func (d *DB) Tx(ctx context.Context, fn func(tx *sql.Tx) error) error {
	tx, err := d.BeginTx(ctx, nil)
	if err != nil {
		return err
	}
	if err := fn(tx); err != nil {
		_ = tx.Rollback()
		return err
	}
	return tx.Commit()
}
```

## 逐段解释与知识点

Config.normalize 过滤空 Kafka broker，解释了“未设变量时 Kafka 可禁用”的现象；这种降级是该字段的实现策略，不代表所有依赖都可以缺失。

`*sql.DB` 是可并发复用的池，`*sql.Tx` 绑定事务连接。Tx 回调内必须用 tx.ExecContext，而不是跳回池执行一条“事务外 SQL”。当前 Tx helper 对正常错误回滚，但没有 defer 回滚覆盖回调 panic，练习可以补这个边界。

日志中的 `%w` 包装错误便于上层 errors.Is/As；业务 code 用 proto 枚举统一。errcode.FromError 对未知错误当前按参数错兜底，扩展功能应留意是否适合自己的系统错误分类。

## 怎么验证与定位错误

执行 `go test ./internal/common/errcode ./pkg/codec`；配置加载用临时 YAML 测正确配置、空 name、非法分片数和错误池参数。DB 故意设置错误地址，期望在预算内失败并包含“ping mysql”上下文，而不是进程永久等待。

在事务测试中让第二次 SQL 返回错误，确认第一次没有提交。使用真实数据库验证时只操作练习库。

## 独立练习与通过标准

增加一个必要配置校验，写明缺失、非法和有效三种行为；用一个小事务证明回滚。通过标准：配置失败不启动监听，日志能辨别读取、解析、验证和连接失败。
