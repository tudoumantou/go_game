## 三种代码标记

1. **源码节选**：当前仓库实现，保留真实签名；通常需要同包其他代码才能编译。
2. **教学实现**：为了分阶段理解而编写，可与当前实现有所不同；明确标记运行方式或放置位置。
3. **改进方案 / 扩展练习**：尚未接入运行中的服务，不能把示例协议号或文件名当作现成功能。

每章包含目标、前置条件、文件清单、实现顺序、带注释的核心代码、知识点、验证步骤、错误排查和练习。学习时在独立练习目录搭建，不要先删除当前项目或覆盖生成代码。源码节选中的依赖按前文章节补齐；本教程不是让你将多个节选原样拼到同一个文件。

## 学习前先记住的事实

- 当前构建产物是五个服务加独立 flusher，共六个程序；flusher 复用 Game 配置，不承载客户端请求。
- 外网入口是 Login HTTP 8080 和 Gateway TCP 9001；不是 WebSocket，也没有浏览器游戏页面。
- `account_id`、`player_id`、连接 ID、会话 ID 各有含义，不可混用。
- 一玩家一 Actor 是状态归属方式；当前运行时由多个分片循环调度，不是一玩家一个 goroutine。
- `sql.DB` 是连接池；Actor 与 SQL 事务保护的是不同层面的顺序。
- Token 是随机字符串加 Redis 映射，当前游客链路没有使用 JWT/RSA 签名 Token。
- Kafka、Redis 去重、脏标记都不能单独证明“奖励绝不重发、数据绝不丢失”。
- 当前仓库有任务、装备、技能、公会、组队、活动、跨服与排行榜代码，README 的 P1–P6 概括不是全部源码清单。功能存在与生产完整性是两回事。

## 当前实现值得带着问题阅读的边界

| 位置 | 已核对的现象 | 学习时追问 |
|---|---|---|
| `pkg/actor/mailbox.go` | 满时拒绝新消息并返回 ErrMailboxFull，保留旧消息 | 各调用方是否正确处理拒收并重试或返回失败？ |
| `pkg/actor/system.go` | FNV 后取模；`processed` 在一轮分片遍历中共享 | 注释中的“每 Actor 100 条”和实际预算是否一致？ |
| `internal/game/player/actor.go` | 预加载替换 State 后已调用 setState | 后续重载与新增 State 替换路径是否都保留回调？ |
| `internal/game/server.go` | 非缓存链路等待 SaveMsg.Done；缓存链路由 writebehind worker 消费 Redis 脏队列 | 投递、Redis 提交与 SQL 提交分别在哪里确认？ |
| `pkg/flush/flusher.go` | `nextTick` 按分钟边界调度；FlushAll 已循环处理多批 | 与 writebehind.Worker 的错峰调度（tick 内按 `interval/Partitions` 分摊分区）是否需进一步对齐分钟边界？ |
| `cmd/*/main.go` | Start 在取消后返回 ctx.Err，入口按错误直接退出 | 后续 Shutdown 能否被执行？ |
| `pkg/mq/kafka.go` | 死信写入错误被忽略，随后仍提交 offset | 持久化失败是否会丢消息？ |
| `internal/game/module/mail/mail.go` | 领取状态事务提交后再给内存背包加物品 | 中间崩溃后如何恢复奖励？ |

这些是源码静态审阅结论，不是说所有场景都会失败。本次文档工作不顺带修改这些业务实现；对应教程给出验证方法和改进方向。

## 运行与验证层次

```bash
# 已有项目：根目录执行。会启动本地 Docker 服务。
make docker-up
make smoke
# 普通单测无需把集成测试当作已经跑过。
go test ./...
# 以下会由 testcontainers 创建自己的依赖容器，首次较慢。
go test -tags=integration -timeout 20m ./test/integration/ -v
```

历史部署验收跑通过两个机器人冒烟；学习者仍应在自己的机器重跑。命令列在教程中不代表所有扩展测试已经执行。Go 工具链异常先检查 `go version`、`go env GOROOT GOTOOLDIR`，编译器与标准库版本必须匹配。
