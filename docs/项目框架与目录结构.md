# 项目框架与目录结构

## 1. 技术栈与用途

| 技术 | 当前使用位置 | 选用理由 |
|---|---|---|
| Go module `game_study`，go.mod 声明 1.22 | 全项目 | 五个服务与独立 flusher，共享基础包 |
| 标准库 net / net/http | TCP 网关、HTTP 登录 | 可以直接学习连接与协议边界 |
| Protobuf / gRPC | api/proto、pkg/pb、内部流 | 类型化消息与双向通信 |
| MySQL + database/sql | pkg/db、Repo | 事务、唯一约束、长期存档 |
| go-redis/v9 | pkg/cache | Token、在线状态、幂等、索引 |
| etcd client/v3 | pkg/registry、pkg/rpc/resolver | 租约注册与动态发现 |
| kafka-go | pkg/mq、internal/*/mq | 异步事件与消费组 |
| zap 封装 | pkg/log | JSON 日志和固定服务字段 |
| Prometheus | pkg/metrics、deploy/monitoring | 观察耗时、积压、错误 |
| 自研 Actor / Write-Behind | pkg/actor、pkg/writebehind、pkg/flush | 状态串行化、缓存快照提交与批量持久化 |

依赖版本以 go.mod/go.sum 为准；本项目没有使用参考项目的 xorm、Echo、gorilla/websocket、goconfig 或 AES-CBC 工具包。

## 3. 进入一个功能时先看什么

| 想理解的功能 | 起点 | 追踪方向 |
|---|---|---|
| 游客登录 | `internal/login/handler/auth.go` | AuthService → AccountRepo / TokenRepo |
| 网关握手 | `internal/gateway/router/router.go` | Session → HandshakeServer → SessionCipher |
| 转发到游戏服 | `internal/gateway/server.go` 的 bindToGame | etcd List → backend Pool → Channel |
| 创角 | `internal/game/service/role_service.go` | 校验 → SQL 事务 → bindPlayer |
| 玩家信息 | `internal/game/module/profile/profile.go` | State 快照 → Protobuf → Reply |
| 使用物品 | `internal/game/module/bag/bag.go` | 配置校验 → RemoveItem → AddExp / Emit |
| 存档 | `internal/game/player/cache_actor.go`、`pkg/writebehind` | Redis 快照与脏队列 → worker SQL 事务 → 版本 Ack；非缓存路径见 persist.go |
| 邮件 | `internal/game/module/mail/mail.go` | 查询、行锁、领取状态、内存发奖 |
| 任务 / 活动 | `internal/game/module/quest`、`activity` | EventAware → 进度 → 领取 |
| 装备 / 技能 | `internal/game/module/equip`、`skill` | Repo、配置、属性变动与消耗 |
| 公会 / 组队 | `internal/game/module/guild`、`team` | 多角色共享实体与事务 |
| 七日签到 | `internal/game/module/signin`、`internal/game/player/grant.go` | 日历、领取事实、CommitItems 与未知提交重载 |
| 商店 / 副本 | `internal/game/module/shop`、`copy` | 限购、结算、奖励边界 |
| 匹配 / 战斗 | `internal/game/module/battle/battle.go` | Center 匹配 → Cross 房间 → 回推与结算 |
| 排行 | `internal/center/rank` | 更新、查询、快照与 leader |

`friend`、`partner` 等协议/DDL/配置存在不代表对应玩法已经在 Game.Start 注册。判断实现至少同时查：协议、处理函数、注册位置、持久化路径、测试。

## 4. 生成物

| 输入 | 生成命令 | 输出 | 修改方式 |
|---|---|---|---|
| api/proto/**/*.proto | `make gen-proto` | pkg/pb | 改 proto 后重生成 |
| proto 的 `// @msg` 注解 | `make gen-msgid` | pkg/codec/msgids_gen.go | 改协议注解后重生成 |
| configs/gamedata/xml/*.xml | `make gen-data` | pkg/gamedata | 改 XML 和生成器，勿手改 *_gen.go |
| sql/schema/*.sql | `make gen-db` | pkg/model | 改 DDL 后重生成，业务 SQL 仍可写在 Repo |

生成模型不是迁移：重新生成 Go struct 不会对已存在的 MySQL 执行 ALTER。静态表生成后嵌入/编译进程序；改宿主机 XML 后只重启旧镜像不一定生效，要重新生成并构建。

## 5. 依赖方向与实际例外

推荐方向是入口装配 → 接入 → 领域规则 → 仓储/基础设施。module 通过 Context 与 PlayerState 接口访问状态，不反向导入 player，避免循环依赖。

README 中“pkg 不 import internal”是设计约束；当前 `pkg/codec/packet.go` 导入了 `internal/common/constant`。Go 的 internal 可见性规则允许仓库内这样使用，但它违反本项目预期的基础包边界。学习时先记录这种差异，练习项目可把网络常量下沉到 codec 或独立公共包。

许多模块把 Repo、Module、消息处理放在同一个文件。这是当前文件布局，不意味着后续功能必须都写成大文件。签到练习采用 `repo.go`、`module.go` 和测试分开。

## 6. 缓存分类

Actor State 维护玩家工作状态；模块中的 map 可能是按 player_id 保存的状态或索引；Redis 是进程外状态；gRPC ClientPool 复用连接；gamedata 是静态配置；Flusher.dirty 是待处理集合。它们都可被口头称为缓存，但失效策略、持久性和所有权完全不同。

## 7. 运行文件与持久数据

Docker 使用 `*-docker.yaml`，本机多进程使用 `*-dev.yaml`。部署脚本复制配置、密钥和 SQL 到命名卷，五服务挂载配置只读；数据库使用单独 mysql 卷。`deploy/keys` 的私钥不入 Git，也不进入镜像。
