# 80-02 后续优化清单

> 按优先级排的后续工作，每项含动机、做法、验证方式；状态以代码基线 `497e603` 为准。原则只有一个：**没有验证手段的优化不上清单**。

## 1. 立即可做（半天级，低风险）

### 1.1 合并 7 处 `reply` 为 `module.Reply`

- **动机**：7 个模块各有一份逐字相同的 `reply` 自由函数（实测 49 行）；更关键的是它是 [70-02 重复回包事故](../70-开发过程实录/02-P0响应串号与幂等失效.md) 写法温床之一——各模块私有的 reply 包装让 `convention_test.go` 只能靠「模式匹配私有名」来防守。
- **做法**：在 `module` 包新增：

  ```go
  // Reply 回本请求的响应（唯一入口）。
  //
  // 曾经 7 个模块各有一份逐字相同的私有 reply——重复回包事故（响应串号）
  // 的写法温床。收拢到框架后，AST 守护检查只需认准这一个名字。
  func Reply(ctx *Context, msgID uint32, msg proto.Message) error {
      body, err := proto.Marshal(msg)
      if err != nil {
          return err
      }
      return ctx.Send(msgID, body)
  }
  ```

  7 处删除、调用点改 `module.Reply(...)`。通知类推送**不并入**（协议号不同、语义不同）。
- **验证**：`go build` + 全量测试；然后向任一 Typed handler 注入一次手动回包，`convention_test.go` 必须报错并给出行号（变异验证）。

### 1.2 `Point`/`Rect` 在 spatial 包试点

- **动机**：坐标以 `(x, y int32)` 散传、区域以 `(x, y, w, h int32)` 四参传递，`inArea(px, py, ax, ay, aw, ah)` 这类调用点**参数顺序写反编译期不报错**，只能靠运行时结果发现。
- **做法**：引入值类型 `Point{X, Y int32}` / `Rect{X, Y, W, H int32}` + `Contains`/`Overlap`/`Center` 方法；风格对齐 scenemap 已有的 `GridPos`。先在 `internal/worldmap/spatial` 一个包内试点，跑通了再向 scenemap 推广。
- **验证**：包内单测（边界：点在边上、矩形相接、负坐标）+ 现有场景测试全绿。

### 1.3 文档路径存在性 CI 检查

- **动机**：`docs/` 下架构研究 50 篇互相引用 225 处，链接腐烂后文档价值打折——本轮就发现过指向 `docs/示例/` 子目录的错误写法（实际在 `docs/` 根）。
- **做法**：一个脚本提取所有 md 里的相对链接（排除 http/锚点），断言目标文件存在；接在 CI 第 ④ 步（go test）之后，与「benchmark 只记录」同一逻辑——文档检查失败应该卡门禁，因为它是确定性的。
- **验证**：故意删一篇文档或改错一个链接，CI 必须红。

## 2. 需先评审（1~2 天，中风险）

### 2.1 配置表列名语义化（36 表 / 280 处）

- **动机**：[70-08 三处配置漂移](../70-开发过程实录/08-配置漂移修复.md) 的认知根源是 `Col1`~`Col5`——读代码的人无法从代码看出「这列有没有被用上」，只能打开 xml 对照。
- **前置（用户明确要求）**：先出 `表名 × 列号 → 语义名 → 当前引用处` 的对照表，36 张表一次审完。**语义名取错比 `Col3` 更糟**（比如把「每日限购」命名成 `WeeklyLimit`），所以人工评审不可跳过。
- **做法**：评审通过后改 `tools/gendata` 生成模板（`Col3` → `Cost`），`make gen` 重新生成，调用点机械替换。
- **验证**：全量测试 + 抽查 10 处语义名与 xml 注释逐字一致。

### 2.2 配置引用守护测试

- **动机**：漂移的根因是「表没人引用也不报错」。逐模块人肉核对不可持续，要固化成测试。
- **做法**：新增测试枚举 gamedata 注册的全部表，每张表至少有一个**非测试代码**引用点；「预留表」（如规格未到的 partner_star 子表）进白名单。白名单本身也要评审——它和错误码白名单一样，是一条显式承诺。
- **验证**：变异验证——删掉某张表的唯一引用点，测试必须失败并指出表名。

### 2.3 Ext JSON 迁移工具

- **动机**：Stateful 迁移（[70-04](../70-开发过程实录/04-P1迁往Stateful.md)）把 Ext 从「行结构」改成「业务结构」，生产旧数据需要一次性迁移（demo 环境未涉及，所以现在没有）。
- **做法**：一次性迁移脚本读旧 Ext JSON → 经旧 `fromRow` 得到行 → 新 `ToRow` 逆推业务结构 → 写新 Ext；按 `sql/migrations` 的编号规范落档。
- **验证**：造一份旧结构 Ext 样本 → 跑迁移 → 用新代码读取，结果与迁移前逐字段相等。

## 3. 架构演进（周级，需设计先行）

### 3.1 在线迁移（节点扩缩不踢人）

- **现状**：网关 `bindToGame` 的注释原话——「节点扩缩时取模值跳变，需重连才会迁移（本版本不处理在线迁移）」。现在扩缩容 = 全量玩家重连。
- **做法**：Actor 状态序列化 + presence 切换 + 网关重选路；难点在「迁移窗口内的双写」——可复用现有 epoch 围栏令牌（R2.5）做后写者胜。
- **验证**：集成测试双节点手动迁移：会话不断、状态不丢、迁移期间的下行不丢不错序。

### 3.2 msgID 发号器升级

- **现状**：chat `nextMsgID` = 毫秒时间戳 << 20 | 20 位随机，同毫秒 1000 条时碰撞概率约 48%（[`c441ac2`](../70-开发过程实录/10-停机flaky与持续集成.md) 已把注释从「可忽略」修正为准确量级）。私聊实际峰值远低于每毫秒 100 条，所以当前够用。
- **触发条件**：要做世界频道/大群才需要升级。
- **做法**：「节点 ID + 同节点序列」替代纯随机段；位宽重算（当前毫秒约 2^40.7，左移后必须 < 2^63）。
- **验证**：现有位域边界测试（随机段不侵占时间戳、毫秒单调、不溢出成负数）+ 新发号器的并发唯一性压测。

### 3.3 scenemap 规格 TODO 排期

- **现状**：mgr 的 `buffTickOne` 有 4 条规格占位（时停延迟死亡/召唤超时/脱战恢复/buff 周期），接入点已留好，刻意没写假实现（见 [50-游戏服/12](../50-游戏服/12-场景scenemap.md)）。
- **做法**：随玩法规格到位逐项落地；每项配不变量测试，复用 Timer 注入手法（[70-01](../70-开发过程实录/01-定时器测试flaky修复.md)）驱动时间。
- **验证**：每项的不变量测试 + 30 次 race 重复。

### 3.4 压测常态化

- **现状**：`test/robot` 压测客户端 + `reports/bench-*` 归档已有骨架；benchmark 进 CI 的结论是「只记录不卡门禁」（[60-04](../60-测试体系/04-集成测试与CI.md)）。
- **做法**：nightly 跑一轮 `make bench`（login/biz/biz-ro/conn 四场景），产出对比报告归档到 `reports/`；趋势劣化超过阈值发通知（不卡 CI）。
- **验证**：连续跑 7 天，数字波动在预期带宽内（否则先修机器噪音，别急着「优化」）。

## 5. 不建议做

- **追新依赖**：现版本锁（Go 1.22 / lint v1.64.8 / buf 1.74.0）是为一致性服务的，升级要有对应收益（唯一有具体收益的候选是 Go 1.23 的定时器语义变化能让 `repeatingTimer.Reset` 的排空代码退役，但仍需全量 race 验证后再动）。
- **为「设计优雅」重构稳定模块**：moduletest、writebehind 这些被测试充分覆盖的包，没有具体缺陷驱动不动它。
- **把清单当 KPI**：10 项全部做完不会有任何用户可见收益；按需取用，哪项有对应的真实痛点先做哪项。

## 6. 小结

清单的排布逻辑：**先收割低风险高信号的（1.1~1.3），再启动需评审的（2.1~2.3），架构项（3.1~3.4）等需求驱动**。每条都带验证手段——这是从这一轮十个专题继承的最重要习惯：没有变异验证的优化，不算完成。
