# 数据库迁移

## 两种场景，两个命令

| 场景 | 命令 | 说明 |
|---|---|---|
| **新库初始化** | `make db-init` | 按 `sql/schema/*.sql` 建全量表；随后 `make db-migrate -- --baseline` 把基线标记为已应用 |
| **已有库升级** | `make db-migrate` | 只执行 `sql/migrations/` 下尚未应用的增量脚本 |

`schema_migrations(version, applied_at)` 记录已执行的文件名。脚本按文件名排序执行，
已记录的直接跳过——重复执行 `make db-migrate` 是安全的。

## 写一个迁移

1. 文件名：`0002_<一句话描述>.sql`，序号递增、不复用。
2. 只写增量：`ALTER TABLE ... ADD COLUMN`、`CREATE TABLE ...`、必要的回填 `UPDATE`。
3. 不要在迁移里删列/改类型：游戏库线上回滚成本极高。

## 回退策略（明确不做自动 down）

MySQL 的 DDL 隐式提交，事务回滚不了；自动 `down` 脚本在删列场景还会丢数据。
本项目采用**只前滚**：

| 变更类型 | 做法 |
|---|---|
| 加列 / 加表 / 加索引 | 直接加，旧代码忽略新列，可随时回退代码 |
| 改语义 / 改类型 | 加新列 → 双写 → 回填 → 切读 → 观察一个版本 → 再删旧列 |
| 删表 / 删列 | 至少保留一个发布周期，确认无读取方后再删 |

`scripts/db-migrate.sh` 在任一迁移失败时立即退出，**不继续后面的迁移**：
半套 schema 比停在旧版本更难排查。
